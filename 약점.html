대회 경쟁력 및 약점 분석

분석 기준일: 2026년 11월 10일 · 대상: 현재 저장소 코드·기획서 및 공식 대회 안내

우승을 노려볼 만한 주제다. 다만 현재 상태는 시연이 강한 프로토타입이며, 실제 데이터 분석의 깊이와 검증 근거를 보강해야 한다.

경쟁작과 세부 심사 배점을 확인하지 못했으므로 우승 확률이나 예상 순위는 산정하지 않았다. 아래 경쟁력 평가는 공식 배점표가 아닌 코드와 공고 목적에 따른 판단이다.

1. 대회 목적과 현재 프로젝트의 차이

공고의 핵심은 비전문가인 도민도 제주빅데이터센터에서 직접 실행할 수 있는 데이터 탐색·분석 자동화 Agent다. 지정 기관 데이터 1종 이상 활용이 필수다. 현재 프로젝트는 주민 신고 대응 흐름이 강하지만, 실제 공공데이터 분석은 상대적으로 주변에 배치되어 있다. 공식 안내

제주 지역문제 연결강함광령리 악취라는 구체적인 문제와 주민·농장·담당부서

2. 현재 프로젝트의 강점

  • 사용자와 행동이 구체적이다. 주민 신고를 접수한 뒤 농장 점검 요청, 담당부서 연락 기록, 민원서 승인까지 이어진다.
  • 분석 Agent가 실제 도구를 호출한다. 신고 집계·시간대 분석·사건 이력·실측 통계·시설 통계를 선택하고 결과를 설명한다.
  • 실제 자료가 포함되어 있다. 저장소에서 실측 391건과 시설현황 58건을 확인했다. 원자료의 정확성·출처·수집 과정은 추가 검증 대상이다.
  • 규칙 기반 대체 경로가 있다. Claude 연결이 없어도 핵심 신고 시연이 가능하다.
  • 근거를 드러내는 구조가 있다. 분석 도구의 입력과 출력이 표시되어 분석 과정을 검토할 수 있다.

3. 우승 경쟁력을 제한하는 핵심 약점

① 주된 시연 가치가 가상 신고에 의존한다

아침 신고를 생성하고 경보·민원서를 만드는 흐름은 명확하다. 그러나 실제 공공자료가 어떤 의사결정을 개선하는지는 덜 선명하다. 가상 기록을 불러오지 않아도 실제 자료만으로 유용한 분석 결과가 나와야 한다.

예상 질문: “주민 신고가 아직 없는 센터 PC에서 이 서비스를 켜면 무엇을 분석할 수 있나요?”

② 기획서와 구현 사이에 차이가 있다

기획서 설명현재 구현조치
시설현황 목록으로 알림 대상 선정별도 실측 농장 4곳 목록 사용구현하거나 향후 계획으로 명시
인구 대비 보정으로 판단임시 인구로 지표 표시, 단계 판단에는 미사용설명 수정 및 임시 지표 처리
10 미만 셀 마스킹분석 도구에서 일관되게 구현되지 않음정책을 정하고 실제 적용
카카오톡 처리 상황 안내웹 시뮬레이터이며 실제 카카오 연동 없음시뮬레이션 범위 명확화
보고서 등 일부 기능향후 계획 또는 부분 구현구현 완료·시연·계획 구분

기획서의 ‘민원 68%’, ‘민원 1,778건’, ‘관리 농가 약 180곳’은 검토한 저장소만으로 원자료와 계산을 재현하지 못했다. 틀렸다는 의미는 아니며, 출처와 산식을 첨부하거나 검증 불가능한 주장은 제외해야 한다.

③ 결과의 정확성과 출처를 신뢰할 근거가 부족하다

  • 규칙 해석기에서 “이제 냄새 안 나요”가 강도 3 신고로 접수되는 것을 재현했다.
  • 기상 API는 미연결인데 키가 설정되면 고정 풍향의 출처가 ‘기상청’으로 표시된다.
  • 일반 아침 시연 기록은 통계에서 가상 데이터로 식별되지 않는다. 현재 가상 여부는 주로 사용자 ID의 sim_ 접두어로 판단한다.
  • 3시간 후 재신고만으로 지속 단계가 될 수 있어, 중간 해소와 재발을 구분하지 못한다.
  • 신고 문장에서 시각을 추출하지만 집계에는 접수 시각을 사용한다.

④ 저장·권한·실행 재현성이 미완성이다

상태가 메모리에 있어 재시작 시 신고와 승인 이력이 사라진다. 인증 없이 농장 응답·대표 승인이 가능하고 전체 상태 API는 신고 원문·사용자 ID·농장 수신함을 반환한다. 공개 운영을 하려면 역할별 접근 제어가 필요하다. 지도 라이브러리의 외부 CDN 의존성도 시연 환경에서 확인해야 한다.

4. 우승을 목표로 한 추천 방향

냄새알림 — 주민 신고와 공공 실측자료를 근거로, 악취 조사 시점과 대응을 돕는 분석 Agent

기존 대응 기능을 유지하면서 대표 시연을 질문 → 데이터 선택 → 분석 → 근거 → 활용 가능한 결과물로 구성한다. 가장 투자 가치가 큰 추가 기능은 ‘조사 시간대 검토 보고서’다.

대표 질문: “광령리 악취 조사에서 추가로 살펴볼 시간대가 있어?”

  1. 사용 가능한 자료, 지역 범위, 관측 기간을 확인한다.
  2. 실측 시간대별 표본 수·초과 건수·초과율을 도구로 계산한다.
  3. 실제 신고 자료가 있으면 같은 지역·기간에 맞춰 분포를 비교한다.
  4. 관측이 적은 시간대와 추가 검토할 사항을 제시한다.
  5. 출처·조건·한계를 포함한 보고서를 생성한다.

분석의 한계: 측정이 없다는 사실만으로 악취가 심하다고 결론 내리지 않는다. 신고가 없다고 악취가 없다고 판단하지 않는다. 지역·기간이 다른 자료는 직접 비교하지 않고, 분기별 소수 측정만으로 농장 개선 효과나 입지 위험을 단정하지 않는다.

현재 대응 단계와 행동은 규칙 엔진이 결정하고, LLM은 문장 해석과 분석 도구 선택·설명을 맡는다. 이 역할 분담을 정확하게 설명해야 한다. 도구가 계산하더라도 최종 LLM 답변의 수치 정확성은 별도로 검증해야 한다.

5. 개발 우선순위

P0 · 필수 판단 오류와 신뢰성 수정

  • 부정문·해소·재발 구분, 반복 신고의 평균 강도 왜곡 방지, 발생 시각과 접수 시각 구분.
  • 실제·가상 데이터를 명시적 속성으로 구분하고 화면·분석 결과에 표시.
  • 기상 출처 오류 수정, 임시 인구 지표 제거 또는 임시값 명시.
  • 실측 단위·초과 기준·출처·이용조건 확인.
  • 기획서의 수치·기능 설명을 구현과 일치시키고 근거 첨부.

P1 · 경쟁력 실제 데이터 분석과 검증

  • 실제 자료만으로 동작하는 조사 시간대 분석·보고서 완성.
  • 분석마다 기간·표본 수·출처·기준일 표시.
  • SQLite 저장과 재시작 복원.
  • 실제 Claude API·도구 실행의 종단 검증.
  • 비전문가용 시작 화면과 예시 질문 제공.

P2 · 여유 시 운영 보완

  • 실제 기상자료 연결과 역할별 접근 제어.
  • 실사용자 대상 사용성 확인과 실행 환경의 외부 의존성 축소.

우선순위를 내릴 기능: 실제 카카오톡 연동, 실제 전화 발신, 입지 리스크 평가, 농장 순위표. 이번 제출에서는 핵심 분석과 검증에 집중한다.

7. 제출 일정과 준비물

공식 마감은 2026년 11월 20일 오전 10시다. 기획서는 15페이지 이내이며, 소스·매뉴얼·데이터 활용 명세·결과 설명자료를 포함한 ZIP이 필요하다. 외부 AI API 평가용 키와 비용은 참가자가 준비해야 한다. 최신 변경은 공식 규정에서 재확인한다.

기간목표
11/10~11/12데이터 근거 확인, 판단 오류 수정, 제출 범위 확정
11/13~11/15핵심 분석·보고서 완성, 실제 LLM 검증
11/16~11/17정확도·사용성·Windows 실행 검증
11/18~11/19기획서 수정, ZIP 검수, 제출 완료
가장 중요한 투자: 실제 데이터로 유용한 분석 하나를 완성하고, 정확성과 사용성을 증명한다.

검토 범위: 소스·기획서 검토 및 규칙 기반 엔진 실행. 아침 12건 → 경보 → 3시간 뒤 재신고 → 민원서 생성 흐름을 확인했다. 같은 사용자 20회 신고는 주민 수 1명으로 집계되지만 신고 건수와 평균에는 반복 입력이 반영된다. 웹 화면과 실제 Claude API 호출은 이 분석에서 검증하지 않았다.
